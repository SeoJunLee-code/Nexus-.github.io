    How to rebuild

    사이트 데이터 다시 만들기

    1. 데이터 재생성과 검사

    • build_data.py 는 표준 라이브러리만 씁니다 (Python 3.9+).
    • --check 는 다시 만든 결과가 커밋된 data/ 와 같은지 비교합니다 (빌드 시각 제외).
    • H1 원자료 h1v2_*.jsonl 이 data_raw/ 에 있으면 문제별 집계를 다시 만들고, 없으면 커밋된 h1_problem_rows.json 을 씁니다.

    2. 사이트 열기

    • 정적 사이트입니다. 빌드 도구나 프레임워크가 없습니다.
    • file:// 로 직접 열면 브라우저가 fetch 를 막아 데이터가 보이지 않습니다 — 로컬 서버로 여세요.
    • GitHub Pages 에 올릴 때는 nexus/ 폴더 내용을 저장소 루트(또는 /docs)에 두면 모든 링크가 상대 경로라 그대로 동작합니다.

    3. 원래 분석 다시 돌리기 (Colab)

    • code/*.py 는 Colab 셀 원본 그대로입니다 (Drive 원본과 바이트 수 일치).
    • H1 — H1_STEP4_cell.py 는 Qwen2.5-Instruct 모델로 문제당 16개 답을 생성합니다 (GPU 필요, 결과는 Drive 에 jsonl 로 저장).
    • Paper 5 1i — Drive 의 phase1_signals/<폴더>/seeds/seed*_k*.json.gz 에피소드 로그를 읽습니다. 이 로그는 저장소에 없습니다.
    • 1j — 1i 원본 파일을 읽어 SHA-256 을 확인한 뒤 두 곳만 바꿔 실행합니다. 해시가 다르면 멈춥니다. 실행 전

    4. 테스트

    build_data.py 의 H1 계산을 원본 셀의 함수(_enrich, _bf, _lb, _boot)와 직접 비교하고, 1i 코드 해시·PREREG 해시·데이터 파일 정합성을 확인합니다.
